# Restaurant Visitor Forecasting

Прогнозирование количества посетителей ресторанных точек на 7 дней вперёд.

---

## Описание проекта

Проект прогнозирует количество посетителей ресторанных точек на **7 дней вперёд**.
Модель может использоваться для планирования загрузки точек, оптимизации персонала и закупок.

- **Целевая переменная:** `guests` — количество посетителей ресторана за день.
- **Дополнительный бизнес-показатель:** `revenue` — дневная выручка.

**Цель проекта** — построить модель прогнозирования спроса, которая может использоваться для планирования загрузки точек и оптимизации ресурсов.

---

## Датасет

Используется датасет [Rossmann Store Sales](https://www.kaggle.com/competitions/rossmann-store-sales/data).

**Исходные данные содержат:**

- дату;
- идентификатор точки;
- продажи;
- количество клиентов;
- информацию о работе точки (открыта/закрыта, промо, праздники).

**Преобразование колонок:**

| Исходная колонка | Колонка в проекте |
|------------------|-------------------|
| `Store`          | `restaurant_id`   |
| `Customers`      | `guests`          |
| `Sales`          | `revenue`         |
| `Date`           | `date`            |

> Исходный датасет **не хранится в репозитории** из-за размера (~38 МБ).
> Скачайте `train.csv` с Kaggle и положите в `data/raw/train.csv`.

### Особенность данных Rossmann

В датасете **отсутствуют воскресенья** — магазины сети закрыты по воскресеньям. Это создаёт пропуски в датах и влияет на:

- расчёт лагов (`lag_7` может быть не «7 дней назад», а «6 дней назад»);
- расчёт скользящих средних (окно `.rolling(28)` «плывёт»);
- проверки «достаточно ли истории» (нельзя проверять `len(history) < 28`).

В пайплайне это обрабатывается:

- проверкой **календарных дней**, а не количества строк;
- заполнением `NaN` в rolling-признаках **медианой по последним 60 дням**;
- сортировкой данных по дате перед расчётом лагов.

## Feature Engineering

Генерация признаков реализована в `src/features.py` (функция `make_features`).

### Календарные признаки

- `day_of_week` — день недели (0–6);
- `month` — месяц (1–12);
- `day_of_month` — день месяца (1–31);
- `is_weekend` — флаг выходного дня.

### Лаговые признаки

- `lag_1` — количество посетителей предыдущего дня;
- `lag_7` — количество посетителей неделю назад;
- `lag_14` — количество посетителей 14 дней назад.

### Скользящие статистики

- `rolling_mean_7` — среднее за последние 7 дней;
- `rolling_mean_28` — среднее за последние 28 дней.

### Признаки, используемые моделью

Итоговый набор признаков модели (порядок важен для CatBoost):

```python
MODEL_FEATURES = [
    'restaurant_id', 'revenue', 'day_of_week', 'month', 'day_of_month',
    'is_weekend', 'lag_1', 'lag_7', 'lag_14',
    'rolling_mean_7', 'rolling_mean_28',
]
```

> **Принцип:** все временные признаки рассчитываются **только на основе прошлых данных** (no data leakage).

## Валидация

Используется **временное разделение** — случайное перемешивание не применяется.

| Разбиение   | Период                    |
|-------------|---------------------------|
| Train       | 2013-01-29 — 2015-06-19   |
| Validation  | 2015-06-20 — 2015-07-31   |

Такой подход позволяет оценить качество модели на будущем периоде, как в реальной эксплуатации.

## Модели

Протестировано 3 подхода:

### 1. Baseline (сезонный наивный прогноз)

Прогноз = значение `guests` за 7 дней до текущей даты.
Учитывает недельную сезонность. Используется как точка сравнения.

### 2. Ridge Regression

Линейная модель на временных признаках.

### 3. CatBoost (основная модель)

`CatBoostRegressor` — выбран, так как хорошо работает с табличными данными и улавливает нелинейные зависимости.

---

## Результаты моделей

Метрики: **MAE** (средняя абсолютная ошибка), **MAPE** (средняя абсолютная процентная ошибка).

| Модель             | MAE   | MAPE  |
|--------------------|-------|-------|
| Baseline (lag_7)   | 163.4 | 24.9% |
| Ridge Regression   | 69.7  | 10.3% |
| **CatBoost**       | **49.8** | **7.1%** |

**Улучшение относительно baseline:**

- MAE: **163.4 → 49.8** (−69%);
- MAPE: **24.9% → 7.1%** (−71%).

## Как работает `predict.py`

1. Загружает обработанные данные, фильтрует по `restaurant_id`, сортирует по дате.
2. Проверяет, что до даты прогноза есть **минимум 28 календарных дней** истории.
3. Загружает модель через `src/model.py`.
4. **Рекурсивный цикл на 7 дней:**
   - создаёт строку для будущего дня (`guests = NaN`);
   - добавляет её к историческим данным;
   - вызывает `make_features()` для расчёта лагов и rolling-средних;
   - заполняет `NaN` медианой по последним 60 дням (из-за пропущенных воскресений);
   - приводит порядок признаков к `MODEL_FEATURES` (CatBoost строго проверяет порядок);
   - получает прогноз через `model.predict(X)`;
   - добавляет прогноз как «реальность» для следующего шага.
5. Возвращает DataFrame с датами и прогнозами.

## Ограничения и допущения

1. **Закрытые дни исключены** из обучающей выборки (`Open == 0`). Цель — прогноз для работающих точек.
2. **Будущая выручка неизвестна** на момент прогноза — используется последнее доступное значение `revenue`.
3. **Затухание прогноза.** На 4–7 день прогнозы сходятся к среднему уровню ресторана, так как модель не получает новых реальных данных и использует собственные предсказания как вход.
4. **Пропущенные воскресенья** заполняются медианой для rolling-признаков.
5. **Горизонт 7 дней** выбран как компромисс между точностью и практической ценностью.
