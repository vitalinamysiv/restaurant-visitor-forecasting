# Restaurant Visitor Forecasting

## Описание проекта

Проект направлен на прогнозирование количества посетителей ресторанных точек на следующие 7 дней.

Целевая переменная:

- `guests` — количество посетителей ресторана за день.

Дополнительный бизнес-показатель:

- `revenue` — дневная выручка.

Цель проекта — построить модель прогнозирования спроса, которая может использоваться для планирования загрузки точек и оптимизации ресурсов.

---

# Датасет

Использован открытый датасет **Rossmann Store Sales**.

Исходные данные содержат ежедневную информацию по торговым точкам:

- дату;
- идентификатор точки;
- продажи;
- количество клиентов;
- информацию о работе точки и календарных событиях.

Для задачи прогнозирования данные были преобразованы:

| Исходная колонка | Использование в проекте |
|---|---|
| `Store` | `restaurant_id` |
| `Customers` | `guests` (целевая переменная) |
| `Sales` | `revenue` |
| `Date` | `date` |

Исходный датасет не хранится в репозитории из-за размера файла.

Перед запуском проекта необходимо разместить исходный файл:


data/raw/train.csv

# Подготовка данных

Подготовка данных выполняется скриптом:


python src/create_dataset.py


Скрипт:

загружает исходный датасет;
оставляет необходимые признаки;
исключает дни, когда точка была закрыта;
переименовывает колонки под задачу прогнозирования;
формирует итоговый датасет:
data/processed/restaurant_daily.csv

Итоговая структура данных:

Колонка	Описание
date	дата наблюдения
restaurant_id	идентификатор точки
guests	количество посетителей
revenue	дневная выручка
Исследование данных (EDA)

EDA выполнен в ноутбуке:

notebooks/01_eda.ipynb

В рамках анализа были исследованы:

динамика количества посетителей во времени;
недельная сезонность;
месячная сезонность;
распределение целевой переменной;
потенциальные выбросы;
пропуски в данных.

Экстремальные значения не удалялись автоматически, так как они могут отражать реальные изменения спроса:

праздники;
акции;
особенности отдельных точек.
Feature Engineering

Генерация признаков реализована в:

src/features.py

Использованные признаки:

Календарные признаки
день недели;
месяц;
день месяца;
признак выходного дня.
Лаговые признаки

Используются исторические значения посещаемости:

lag_1 — количество посетителей предыдущего дня;
lag_7 — количество посетителей неделю назад;
lag_14 — количество посетителей 14 дней назад.
Скользящие статистики

Используются:

rolling_mean_7 — среднее количество посетителей за последние 7 дней;
rolling_mean_28 — среднее количество посетителей за последние 28 дней.

Все временные признаки рассчитываются только с использованием прошлых данных, чтобы избежать утечки информации.

Валидация

Для оценки качества использовалось временное разделение данных.

Случайное перемешивание данных не использовалось.

Разделение:

Train:
2013-01-29 — 2015-06-19

Validation:
2015-06-20 — 2015-07-31

Такой подход позволяет оценивать качество модели на будущем периоде.

Модели

Были протестированы следующие подходы:

1. Baseline

Используется сезонный наивный прогноз:

прогноз = значение количества посетителей за 7 дней до текущей даты

Baseline учитывает недельную сезонность и используется как точка сравнения.

2. Ridge Regression

Линейная модель, использующая созданные временные признаки.

3. CatBoost

Основная модель проекта:

CatBoostRegressor

Преимущества модели:

хорошо работает с табличными данными;
учитывает нелинейные зависимости;
эффективно использует лаговые признаки и календарные факторы.
Результаты моделей

Метрики:

MAE — средняя абсолютная ошибка;
MAPE — средняя абсолютная процентная ошибка.
Модель	MAE	MAPE
Baseline (lag_7)	163.4	24.9%
Ridge Regression	69.7	10.3%
CatBoost	49.8	7.1%

CatBoost показал лучшее качество среди протестированных моделей.

По сравнению с baseline:

MAE снизился с 163.4 до 49.8;
MAPE снизился с 24.9% до 7.1%.

Использование исторических признаков, календарных факторов и скользящих статистик позволило существенно улучшить прогнозирование посещаемости.

Анализ важности признаков

Наиболее важные признаки модели:

Признак	Интерпретация
rolling_mean_28	долгосрочный уровень спроса за последние 28 дней
revenue	показатель масштаба активности точки
lag_1	краткосрочная динамика посещаемости
rolling_mean_7	недельный тренд спроса
day_of_week	недельная сезонность

Модель преимущественно использует исторические показатели спроса, что соответствует специфике задачи прогнозирования временного ряда.

Ограничения и допущения

При прогнозировании будущих дней значение revenue заранее неизвестно.

Для формирования признаков в predict.py используется последнее доступное значение выручки.

В дальнейшем качество прогноза может быть улучшено за счёт отдельного прогнозирования выручки или добавления дополнительных внешних факторов.
