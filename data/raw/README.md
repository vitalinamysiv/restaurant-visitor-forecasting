## Структура исходного `train.csv`

| Колонка          | Описание                                 |
|------------------|------------------------------------------|
| `Store`          | ID магазина                              |
| `DayOfWeek`      | День недели (1–7)                        |
| `Date`           | Дата наблюдения                          |
| `Sales`          | Выручка за день                          |
| `Customers`      | Количество клиентов за день              |
| `Open`           | Магазин открыт (1) или закрыт (0)        |
| `Promo`          | Промо-акция (1) или нет (0)              |
| `StateHoliday`   | Государственный праздник (0 / a / b / c) |
| `SchoolHoliday`  | Школьные каникулы (0/1)                  |

## Как подготовить данные

После того как `train.csv` окажется в этой папке, выполните из корня проекта:

```bash
python src/create_dataset.py
```

Скрипт выполняет следующие шаги:

1. Загружает исходный `train.csv`.
2. Помечает закрытые дни (`Open == 0`) и аномалии (`Sales == 0` при `Open == 1`).
3. Оставляет только открытые дни без аномалий.
4. Переименовывает колонки под схему проекта:
   - `Store → restaurant_id`
   - `Customers → guests`
   - `Sales → revenue`
   - `Date → date`
5. Восстанавливает полный календарь для каждого ресторана.
6. Удаляет строки с пропусками выгрузки.
7. Сохраняет результат в `data/processed/restaurant_daily.csv`.

## Почему данных нет в репозитории

В соответствии с требованиями к проекту, репозиторий не должен содержать датасеты размером более 10 МБ. Файл `train.csv` весит около 38 МБ, поэтому он не коммитится в git.

Вместо этого в репозитории хранится:

- скрипт подготовки данных (`src/create_dataset.py`);
- эта инструкция с описанием источника данных.

Такой подход — стандартная практика в ML-проектах: код в репозитории, данные — отдельно.
